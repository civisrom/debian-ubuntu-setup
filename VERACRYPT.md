# Восстановление /opt из VeraCrypt

`config/opt.hc` заменяет прежний `config/opt.7z`. Это обычный VeraCrypt-контейнер
размером **104857600 байт (100 МиБ)**, с AES, SHA-512, стандартным PIM 0 и без
ключевых файлов. Пароль хранится отдельно и не входит в репозиторий.

100 МиБ — максимальный размер одного файла в обычном GitHub-репозитории при
отправке через Git. Загрузка через браузер ограничена 25 МиБ; Git LFS здесь
не используется. [Ограничения GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

В FAT-файловой системе контейнера находятся `payload.tar.gz` и `payload.sha256`.
Сжатие позволяет экономить место, а архив хранит структуру каталогов. Внешний
контейнер, помощник и Python-модуль проверяются по SHA256, зафиксированным в
`system-setup.sh`. Все три скачиваются из одного commit установщика.

## Обычная установка

Запустите установку по инструкции в README. На вопрос **Restore opt.hc to /opt?**
ответьте `y`, затем введите пароль. Ввод скрыт. Без этого выбора контейнер
не скачивается и VeraCrypt не устанавливается.

При необходимости установщик загрузит VeraCrypt 1.26.29 с официального GitHub,
проверит PGP-подпись пакета и отпечаток ключа
`5069A233D55A0EEB174A5FC3821ACD02680D16DE`, затем установит пакет с зависимостями.
Есть пакеты для Debian 12 amd64, Debian 13 amd64/arm64, Ubuntu 24.04 и 26.04
amd64/arm64. Для Debian 12 arm64 VeraCrypt нужно установить самостоятельно.
Уже установленный VeraCrypt используется без переустановки.
Для монтирования нужны FUSE, loop и поддержка FAT в работающем ядре.
Используется шифрование в процессе VeraCrypt (`nokernelcrypto`), поэтому
наличие AES-XTS в device-mapper не требуется.

Порядок восстановления:

1. Проверка скачанных файлов, открытие контейнера только для чтения.
2. Проверка внутренней контрольной суммы и всего состава архива до записи в `/opt`.
3. Резервная копия затрагиваемых существующих файлов в
   `/var/backups/system-setup/opt-before-*/previous.tar.gz`.
4. Восстановление файлов и прав, проверка байтов каждого записанного файла.
5. Закрытие контейнера и удаление временных расшифрованных файлов.

Файлы `/opt`, которых нет в снимке, сохраняются. Восстанавливаемые файлы и
каталоги принадлежат `root:root`. Каталоги получают `755`, `.git` — `700`;
скрипты `.sh`, `.py`, `.pl` — `755`; обычные данные и MMDB — `644`.
`environment`, `geolite_config`, `.env*`, файлы `.env`, `.ini`, `.json`, `.yaml`,
`.yml`, `.toml`, `.conf`, `.key`, `.pem` и содержимое `.git` получают `600`.
Значения конфигураций не исполняются и не выводятся.

Ссылки, специальные файлы, повторяющиеся или выходящие из каталога пути
отклоняются. При ошибке записи уже заменённые файлы восстанавливаются из
резервной копии. Если размонтирование не удалось, временный каталог сохраняется
и выводится команда закрытия; удалять его до размонтирования нельзя.
При ошибке восстановления основной установщик пропустит установку nftables,
чтобы не применить неполный набор файлов.

Это восстановление **файлов в `/opt`**. Файл `/opt/environment` не заменяет
`/etc/environment`, а `/opt/geolite_config` не заменяет `/etc/geolite_config`.
Если новой программе `nft-full` нужны эти учётные данные MaxMind:

```bash
sudo install -o root -g root -m 600 /opt/geolite_config /etc/geolite_config
```

Правила firewall и сервисы не запускаются самим помощником VeraCrypt; их
настройкой управляют отдельные выбранные шаги основного установщика.

## Отдельная проверка или восстановление

В локальном клоне репозитория:

```bash
# Только открыть контейнер и проверить контрольную сумму, без записи в /opt:
sudo bash config/opt-vault.sh check config/opt.hc

# Восстановить файлы в /opt с резервной копией:
sudo bash config/opt-vault.sh restore config/opt.hc
```

Пароль запросит VeraCrypt. Для автоматизированного запуска разрешён файл с
правами `600` или `400`, содержащий одну строку пароля:

```bash
sudo bash config/opt-vault.sh check config/opt.hc \
  --password-file "$HOME/.config/opt-vault.password"
```

В списке процессов будет только путь файла; значение пароля в аргументы не
передаётся. Файл пароля должен оставаться вне клона и вне каталога, который
будет включён в контейнер. Не добавляйте его в Git и не присылайте в переписку.

## Создание следующего снимка

Помощники `config/opt-vault.sh` и `config/opt-payload.py` должны находиться рядом.
Подготовьте локальный файл пароля с правами `600`. Остановите изменения файлов
в исходном каталоге на время создания снимка. Затем из корня клона:

```bash
sudo bash config/opt-vault.sh create /home/codex/opt config/opt-new.hc \
  --password-file "$HOME/.config/opt-vault.password"
```

Все обычные файлы и каталоги источника, включая скрытые, попадают в контейнер.
Исходник не изменяется. Ссылки и специальные файлы не поддерживаются.
Существующий файл контейнера помощник не перезаписывает. После записи он
закрывает контейнер, повторно открывает только для чтения и проверяет SHA256.
При запуске через sudo созданный файл передаётся пользователю, вызвавшему sudo,
с правами `600`, чтобы его можно было добавить в Git.

После успешной проверки замените `config/opt.hc` новым файлом и обновите
`OPT_VAULT_SHA256` в `system-setup.sh` значением `sha256sum config/opt.hc`.
Если менялись помощники, обновите также `OPT_VAULT_HELPER_SHA256` для
`config/opt-vault.sh` и `OPT_PAYLOAD_SHA256` для `config/opt-payload.py`.
Затем выполните:

```bash
./update-checksum.sh
bash tests/regression.sh
sha256sum -c system-setup.sh.sha256
```

В один commit должны войти контейнер, изменённые помощники, основной скрипт
и его checksum. Пароль и временный незашифрованный архив туда не входят.
Каждая версия контейнера занимает около 100 МиБ в истории Git.

## Восстановление прежних файлов из резервной копии

В каталоге конкретной копии находятся `previous.tar.gz` и `new-paths.txt`.
Первый содержит прежние файлы с прежними владельцами и правами, второй —
только пути, которых не было до восстановления. Каталог копии закрыт правами
`700`, архив — `600`; в нём могут быть прежние секреты.

Для возврата существовавших файлов выберите нужную копию и выполните от root:

```bash
sudo tar -xzpf /var/backups/system-setup/opt-before-ИМЯ/previous.tar.gz -C /opt
```

Эта команда не удаляет новые файлы: при полном ручном откате отдельно проверьте
`new-paths.txt` и удалите только соответствующие пути. Не удаляйте весь `/opt`.
